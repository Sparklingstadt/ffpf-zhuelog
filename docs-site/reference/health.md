# ヘルスチェック

認証もレート制限もかからないルートです。

| メソッド | パス       | DB に触れる | 用途                                 |
| -------- | ---------- | ----------- | ------------------------------------ |
| GET      | `/health`  | はい        | 本番での手動の確認                   |
| GET      | `/healthz` | はい        | `/health` と同じ。ローカルでの確認用 |
| GET      | `/ping`    | いいえ      | ALB のヘルスチェック                 |

## GET /health と GET /healthz

DB に ping（3 秒でタイムアウト）して、届けば `200` を返します。

**レスポンス** `200`

```json
{ "status": "ok" }
```

**エラー**

| HTTP | code          | 状況                                            |
| ---- | ------------- | ----------------------------------------------- |
| 503  | `unavailable` | DB に届かない（「サービスを利用できません。」） |

## GET /ping

DB にアクセスせずに `200` を返します。

**レスポンス** `200`

```json
{ "status": "ok" }
```

ALB のヘルスチェックに `/health` を使わないのは、数秒ごとに DB へアクセスすると Neon のコンピュートが休止できずに費用がかかり続けることと、DB の障害時に ECS が正常なタスクまで入れ替えてしまうことを避けるためです。
