# Go API にゴミ箱・共有・フォローを足す

`docs/superpowers/specs/2026-10-20-go-mobile-api-design.md` の v1 で範囲外にしたゴミ箱・共有・フォローを、ネイティブアプリ向けの Go API（`services/api/`）に足す。

## 承認済みの要件

- 権限と結果は Web と同じにする。同じ DB を Web と同じ条件で読み書きし、Web と API で結果が食い違わないようにする。
- 一覧（ゴミ箱とタイムライン）は、既存の `GET /v1/entries` と同じカーソル方式のページングにする。Web の 100 件での打ち切りはしない。
- DB のスキーマは変えない。

## Web のルール（そのまま従う）

| 機能                                           | 使える人                                 | 対象                                                              |
| ---------------------------------------------- | ---------------------------------------- | ----------------------------------------------------------------- |
| ゴミ箱（一覧・復元・完全削除・空にする）       | admin と会員                             | 自分のエントリーだけ                                              |
| 共有の切り替え                                 | 会員だけ（admin はフォローされないため） | 自分の、ゴミ箱にないエントリー                                    |
| フォロー・フォロー解除・会員一覧・タイムライン | admin と会員                             | フォローできる相手は既存の会員（`password:<id>`）だけ。自分は不可 |

- ゴミ箱に入れても `sharedAt` は消さない。ゴミ箱の中のエントリーは共有中でも一覧やタイムラインに出ない。復元すると再び共有される。
- 共有済みのエントリーをもう一度共有しても、最初の `sharedAt` を保つ。
- 二重のフォローは何も起きない。フォローしていない相手のフォロー解除も成功として扱う。
- 自動でゴミ箱を空にする仕組みはない。

## エンドポイント

すべてアクセストークンが必要で、エラーの形式・`Cache-Control: no-store`・本文の上限は既存の API と同じ。

### ゴミ箱

| メソッド | パス                       | 成功 | 内容                                                                                           |
| -------- | -------------------------- | ---- | ---------------------------------------------------------------------------------------------- |
| GET      | `/v1/trash?cursor=&limit=` | 200  | `{entries, nextCursor}`。各エントリーに `deletedAt` を足す。並びは `(deletedAt DESC, id DESC)` |
| POST     | `/v1/trash/{id}/restore`   | 200  | `deletedAt` を消し、復元したエントリーを返す                                                   |
| DELETE   | `/v1/trash/{id}`           | 204  | 完全に削除する（ヒントも Cascade で消える）                                                    |
| DELETE   | `/v1/trash`                | 200  | `{"deleted": <件数>}`。自分のゴミ箱を全件削除する                                              |

ゴミ箱にない ID、他人の ID、存在しない ID は 404。

### 共有

| メソッド | パス                     | 成功 | 内容                                                        |
| -------- | ------------------------ | ---- | ----------------------------------------------------------- |
| PUT      | `/v1/entries/{id}/share` | 200  | `sharedAt` が空のときだけ現在時刻を入れる。エントリーを返す |
| DELETE   | `/v1/entries/{id}/share` | 200  | `sharedAt` を消す。エントリーを返す                         |

- admin が呼ぶと 403 `forbidden`（メッセージ「共有できるのは会員だけです。」）。
- ゴミ箱の中、他人、存在しない ID は 404。

### フォロー

| メソッド | パス                          | 成功 | 内容                                       |
| -------- | ----------------------------- | ---- | ------------------------------------------ |
| GET      | `/v1/members`                 | 200  | `{members, followingCount, followerCount}` |
| PUT      | `/v1/follows/{ownerId}`       | 204  | フォローする                               |
| DELETE   | `/v1/follows/{ownerId}`       | 204  | フォローをやめる                           |
| GET      | `/v1/timeline?cursor=&limit=` | 200  | `{items, nextCursor}`                      |

- `members`: 自分以外の全会員を `displayName` の順（日本語の照合順）で並べる。各要素は `{ownerId, displayName, loginId, following, followsMe}`。会員数は少ないのでページングしない。
- `followingCount` は、フォローしている相手のうち今も存在する会員の数。`followerCount` は自分をフォローしている行の数（Web と同じ）。
- `{ownerId}` は `^password:[a-z0-9]{1,64}$` に合うものだけを受け付け、合わなければ 404。自分なら 400 `self_follow`（「自分はフォローできません。」）。存在しない会員は 404。
- `items`: 各要素は `{entry, ownerId, ownerName}`。`entry` は既存のエントリーの形、`ownerName` は会員の `displayName`。フォローしている相手の、共有中でゴミ箱にないエントリーを `(createdAt DESC, id DESC)` で返す。退会した会員のエントリーは出さない（SQL で会員の表に結合して除く）。フォローしている相手がいなければ空の配列。

### 一覧の共通ルール

`limit` は既定 50・最大 100。`cursor` は最後の要素の `(並びの時刻, id)` を既存と同じ形式でエンコードしたもの。不正な `limit` や `cursor` は 400。

## 実装の方針

- `store` にゴミ箱・共有・フォロー・会員一覧の SQL を足す。Web の Prisma の条件（`ownerId`、`deletedAt`、`sharedAt`、`Follow` の主キー）をそのまま SQL にする。
- 役割の判定（共有は会員だけ）は `httpapi` のハンドラで、トークンの `role` を見て行う。
- 会員一覧の並びは、Web の `localeCompare(..., "ja")` に合わせて DB の ICU 照合順 `ja-x-icu` で並べる（`ORDER BY "displayName" COLLATE "ja-x-icu", "createdAt", "id"`。同名は Web の `accounts.list()` と同じく作成順）。Go 側では並べ替えない（`golang.org/x/text` は使わない）。本番の Neon にも `ja-x-icu` が必要: `SELECT 1 FROM pg_collation WHERE collname = 'ja-x-icu'` で確認する。
- テストは既存と同じく、`store` は実際の Postgres、`httpapi` はフェイクで行う。

## 範囲外

- 添削・翻訳の実行、admin による他の会員のエントリーの閲覧、フォロワーの一覧の個別表示。
