# Go API に Web の残りの機能を足す

ネイティブアプリ向けの Go API（`services/api/`）に、Web にあって API に無い機能（日付ごとの記録とカレンダー、admin による会員のノートの閲覧、自分のパスワードの変更、admin による会員の管理、CSV のインポート）を足す。

## 承認済みの要件

- 権限と結果は Web と同じにする（同じ DB を Web と同じ条件で読み書きする）。
- DB のスキーマは変えない。
- ゲストのログインは足さない。Web のゲストはノートを何も見られないので、アプリはログインを求める画面で同じ体験になる。
- エラーの形式・トークンの確認・`Cache-Control: no-store` は既存の API と同じ。

## 1. 日付ごとの記録とカレンダー（admin と会員）

| メソッド | パス                                    | 成功 | 内容                                                                                                   |
| -------- | --------------------------------------- | ---- | ------------------------------------------------------------------------------------------------------ |
| GET      | `/v1/log-dates`                         | 200  | `{dates:[{date, count}]}`。ノートがある日付と件数を、新しい日付から順に返す                            |
| GET      | `/v1/log-dates/{date}/entries`          | 200  | `{date, entries}`。その日のノートを古い順に返し、各ノートに `number`（その日の何件目か、1 から）を足す |
| GET      | `/v1/log-dates/{date}/entries/{number}` | 200  | `{entry, number, total}`                                                                               |

- 日付の区切りは Web と同じく日本時間（UTC+9 固定）。`createdAt`（UTC）に 9 時間を足した日付で分ける。ゴミ箱の中のノートは数えない。
- 並びは `(createdAt ASC, id ASC)`。`number` は保存せず、この並びの位置で決める（Web と同じく、前のノートをゴミ箱に入れると後ろの番号が繰り上がる）。
- `{date}` は `YYYY-MM-DD`。年は 2000〜9999。実在しない日付・形式違いは 400。`{number}` は 1 以上 2147483647 以下の整数で、形式違いは 400、範囲外（0 件の日を含む）は 404。
- カレンダーはページングしない（Web と同じく全期間を返す）。

## 2. admin による会員のノートの閲覧（読み取りのみ）

- 次の読み取りのエンドポイントに `?user=<ownerId>` を足す: `GET /v1/entries`、`GET /v1/entries/{id}`、上の 3 つ。
- `?user=` が無い、または自分の ownerId と同じなら自分のノート。
- 自分以外を指定できるのは admin だけ。会員が自分以外を指定すると 403 `forbidden`（「他の人の記録は管理者だけが見られます。」）。Web は黙って自分の記録に切り替えるが、API でそうするとアプリが他人の記録を見ていると誤解するので、エラーにする。
- `?user=` は Web の `isOwnerId` と同じ形式（`^\d+$` か `^password:[a-z0-9]{20,32}$`）だけを受け付け、違えば 400。存在しない ownerId は空の結果（Web と同じ）。
- 書き込み・ゴミ箱・共有・フォロー・CSV には `?user=` を使えない（付けても無視されるのではなく、そもそも受け付けない。既存どおり常に自分）。

## 3. 自分のパスワードの変更（会員だけ）

`POST /v1/account/password` に `{currentPassword, newPassword, confirmPassword}` を送る。成功は 204。

確認の順番は Web の `ChangeOwnPassword` と同じ。

1. `newPassword` が 12〜128 文字（違えば 400 `invalid_request`「パスワードは12〜128文字にしてください。」）。
2. `newPassword` と `confirmPassword` が一致（違えば 400 `password_mismatch`「確認用のパスワードが一致しません。」）。
3. アカウントが無い、`currentPassword` が 1〜128 文字でない、ロック中、パスワード違いは、どれも 400 `invalid_current_password`「現在のパスワードが違うか、一時的にロックされています。」。ロック中・形式違い・アカウントなしでもダミーの scrypt を 1 回計算する。
4. 検証の前に試行を 1 回数える（既存の `ReserveAttempt`、5 回失敗で 15 分ロック）。正しければ、新しいハッシュを保存し、`sessionVersion` を 1 上げ、失敗回数とロックを消す（Web の `setPassword` と同じ 1 文の UPDATE）。

- admin（GitHub）は 403 `forbidden`。
- `sessionVersion` が上がるので、この端末を含め API と Web の既存のログインはすべて無効になる。アプリはログインし直す。
- `/v1/auth/*` と同じレート制限（IP ごとに 1 分 10 回、同じ制限の枠を共有する）をかける。

## 4. admin による会員の管理（admin だけ）

会員は 403 `forbidden`。

| メソッド | パス                               | 成功 | 内容                                                                                                                         |
| -------- | ---------------------------------- | ---- | ---------------------------------------------------------------------------------------------------------------------------- |
| GET      | `/v1/admin/accounts`               | 200  | `{accounts:[{id, ownerId, loginId, displayName, createdAt, locked}]}`。`createdAt ASC, id ASC`。ハッシュと失敗回数は返さない |
| POST     | `/v1/admin/accounts`               | 201  | `{loginId, displayName, password?}` で作る。`{account, password, generated}` を返す                                          |
| POST     | `/v1/admin/accounts/{id}/password` | 200  | `{password?}` でリセットする。`{loginId, password, generated}` を返す                                                        |

- 入力のルールは Web と同じ: `loginId` は前後の空白を除いて小文字にし `^[a-z0-9._-]{3,32}$`、`displayName` は前後の空白を除いて 1〜50 文字、`password` は空（空白だけを含む）なら生成、それ以外は 12〜128 文字（空白は除かない）。違反は 400 `invalid_request` で、項目ごとのメッセージは Web と同じ（「ログインIDは英小文字・数字・. _ - の3〜32文字にしてください。」「表示名は1〜50文字にしてください。」「パスワードは12〜128文字にしてください。」）。
- 生成するパスワードはランダムな 15 バイトの base64url（Web の `generate()` と同じ）。ハッシュは既存の scrypt（N=32768, r=8, p=1）。
- ログイン ID の重複は 409 `login_id_taken`「このログインIDはすでに使われています。」。リセットで会員が無ければ 404「アカウントが見つかりません。」。
- リセットは `sessionVersion` を上げ、失敗回数とロックを消す（その会員の既存のログインはすべて無効になる）。
- 返したパスワードはこの 1 回だけで、ログにも出さない。`locked` は `lockedUntil > now`。
- 会員の削除は Web にも無いので足さない。

## 5. CSV のインポート（admin と会員。自分のノートにだけ入れる）

`POST /v1/imports/csv` に `multipart/form-data` の `csvFile` を送る。成功は 201 `{batch: {id, importedAt}, count}`。

- ファイルが無い・空 → 400「CSVファイルを選択してください。」。5 MiB を超える → 413「ファイルは5MB以下にしてください。」。名前が `.csv` で終わらない（大文字小文字は区別しない）→ 400「拡張子が.csvのファイルを選択してください。」。このエンドポイントだけ本文の上限を 6 MiB にする（マルチパートの余白を含む）。
- 解析のルールは Web の `CsvParseLearningParser` と同じ:
  - BOM を無視、空行を飛ばす、列数の違いを許す、各セルの前後の空白を除く、1 レコード 10 万文字まで。
  - 1 行目は、3 列以上で最初の 3 つ（空白を除いて小文字にしたもの）が「最初の文／原文／original」「添削後の文／添削文／corrected」「ピン音／拼音／pinyin」なら見出しとして飛ばす。
  - 列は、最初の文・添削後の文・ピン音・ヒント 1〜100。空のヒントは捨てて位置を詰める。`kind` は常に `correction`。
  - 上限: データ行 1000 行、1 セル 1 万文字、ヒント 100 列。
- エラーは 400 `invalid_csv` で、メッセージは Web と同じ文言:
  - 「CSVの形式を確認してください。引用符が閉じていないか、1行が長すぎる可能性があります。」
  - 「一度にインポートできるのは1000件までです。」「CSVにデータ行がありません。」
  - 「{行}行目は3列未満です。」「{行}行目は上限（各項目1万文字・ヒント100列）を超えています。」「{行}行目の「最初の文」「添削後の文」「ピン音」は必須です。」（行は見出しを含めた 1 始まりの CSV の行番号）
- 全件を確認してから、既存の `CreateBatch` と同じく 1 トランザクションで `ImportBatch`（`fileName` は送られたファイル名を 255 文字までに切ったもの、`rowCount`）とノートを保存する。
- Web と同じ CSV で同じ結果になることを、共通のテストデータ（正常・見出しあり・各エラー）で確かめる。

## 範囲外

- ゲストのログイン、会員の削除、admin による会員のノートの書き込み。
