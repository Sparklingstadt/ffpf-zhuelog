# 段階 11 の参照：Go のログイン（GitHub・パスワード・FFPF ID・ゲスト・デモ・ログアウト・回数の制限）と、Web の今のセッションの動き（2026-11-17 時点）

All Go paths relative to `services/api/`. Web paths relative to repo root. Written as the reference for both plans of stage 11: docs/superpowers/plans/2026-11-16-deprecate-go-stage11a-sessions.md (the `Session` table, the web's own sign-in code and the OAuth clients, not yet wired) and docs/superpowers/plans/2026-11-16-deprecate-go-stage11b-switch.md (the web signs in itself, the proxy and the current user read `Session`, Go's sign-in is deleted). Stages 1–10c are merged into this branch: the web decides who is signed in itself from Go's access token (`getCachedCurrentUser`, `src/composition/current-user.ts`), writes every table but `ApiRefreshToken` through Prisma, and runs LINE and the two crons. **Go keeps only sign-in** (`/v1/auth/*`, `/v1/me`) and the health routes.

## 0. Routes, registration, who may call

`newMux` (httpapi/router.go:99-106) registers four groups; nothing else is left in Go.

| Route                     | Registered (router.go)  | Wrapper, outermost first                           | Handler                                           |
| ------------------------- | ----------------------- | -------------------------------------------------- | ------------------------------------------------- |
| `GET /health`, `/healthz` | `healthRoutes` :143-152 | public                                             | `healthz` :187-200 (DB ping, 3 s, 503 on failure) |
| `GET /ping`               | same                    | public                                             | `ping` :181-185 (no DB)                           |
| `POST /v1/auth/github`    | `authRoutes` :154-164   | `limited` (route limit)                            | `loginGitHub` auth_handlers.go:48-71              |
| `POST /v1/auth/ffpf`      | same                    | `limited`                                          | `loginFFPF` auth_handlers.go:75-99                |
| `POST /v1/auth/password`  | same                    | `limited`                                          | `loginPassword` auth_handlers.go:101-120          |
| `POST /v1/auth/refresh`   | same                    | `refreshLimited` (its own, looser limit)           | `refresh` auth_handlers.go:126-140                |
| `POST /v1/auth/logout`    | same                    | `limited`                                          | `logout` auth_handlers.go:142-155                 |

- The `Auth` interface (router.go:21-33) is the whole sign-in surface: `LoginGitHub`, `LoginFFPF`, `LoginPassword`, `Refresh`, `Logout`, `Authenticate`, `LoginGuest`, `Me`, `ActAs`, `DemoEnabled`, `LoginDemo`.
- Unregistered routes → **404** `{"error":{"code":"not_found","message":"見つかりません。"}}`, wrong method → **405** with `Allow` (`jsonMuxErrors` router.go:204-224).
- Every answer has `Cache-Control: no-store` (`noStore` middleware.go:121-126, `writeJSON` respond.go:66-77). Bodies are capped at 1 MiB (`limitBody` middleware.go:129-134, `maxBodyBytes` :18).
- Body decoding (`decodeBody` respond.go:142-160): exactly one JSON object, unknown fields refused, trailing data refused; a `jsonString` field refuses `null` (auth_handlers.go:34-46) → **400** `invalid_request` 「リクエストが不正です。」; over 1 MiB → **413** `too_large`. The guest and demo bodies may be empty or `{}` (`io.EOF` accepted, auth_handlers.go:162, demo.go:28).
- Successful sign-ins and refresh answer **200** `{"accessToken","refreshToken","expiresIn":900,"refreshExpiresIn":2592000|86400}` (`tokenResponse` auth_handlers.go:13-29). Logout answers **204**.
- Error mapping (`writeServiceError` respond.go:97-122): `ErrUnauthorized` → 401 `unauthorized` 「認証が必要です。」; `ErrForbidden` → 403 `forbidden` 「このアカウントは利用できません。」; `ErrThrottled` → 429 `rate_limited` 「しばらくしてから再度お試しください。」; `ErrGitHubUnavailable` → 502 `github_unavailable` 「GitHub に接続できませんでした。」; `ErrFFPFUnavailable` → 502 `ffpf_unavailable` 「FFPF ID に接続できませんでした。」; `ErrDemoDisabled` → 404 `not_found` 「デモは利用できません。」; `ErrFFPFDisabled` → 503 `unavailable` 「サービスを利用できません。」; anything else is logged as `"request failed"` with the error text (never secrets, see §12) → 500 `internal` 「サーバーでエラーが発生しました。」.
- None of these messages reaches a person any more: the web maps every failure to its own `/signin?error=…` keys (§11.4). The web need not reproduce Go's JSON shapes.

## 2. Client address, the route limit and the proxy secret

- `clientKeyFunc` (middleware.go:260-270): when `X-Zhuelog-Proxy-Secret` matches `API_WEB_PROXY_SECRET` (constant time) and `X-Zhuelog-Client-IP` is non-blank, that header is the client; otherwise `peerKey` (:285-302) = the last value of the last `X-Forwarded-For` line, else `RemoteAddr`'s host. The web always sends both headers with `clientAddress(headers)` (`src/infrastructure/go-api/client.ts:68-79`), so in production the key is **the web's** `clientAddress`.
- `auth.ClientAddress` (auth/client.go:18-41) normalises again: IPv4 (and IPv4-mapped) dotted, IPv6 as its /64 `a:b:c:d::/64` (four lowercase hex groups, no leading zeros), anything else `unknown`. The web's `normaliseClientAddress` (`src/infrastructure/auth/client-address.ts:14-40`) is the same function (`tests/client-address.test.ts` "client addresses normalise like the Go API's auth.ClientAddress"), and `clientAddress` (:6-9) takes `x-real-ip`, else the first `x-forwarded-for` value. Normalising twice is idempotent, so **the keys Go writes are exactly `<prefix><clientAddress(headers)>`**. Go's route limit (`rateLimit`) keys on `clientKey(r)` without `ClientAddress`, and `LoginPassword`/`LoginDemo` on `ClientAddress(clientKey(r))`; since the web already sends the normalised address, both are the web's `clientAddress(headers)` in production (they would differ only for a caller that is not the web, e.g. a raw IPv6 address).
- Route limit (`newRegistrar` router.go:122-133, `rateLimit` middleware.go:306-320, `throttleLimiter` :336-346): `SignInThrottle` key `route:auth:<client>`, **10 per 1 minute** (`authRateLimit`/`authRateWindow` router.go:62-63) on github, ffpf, password, logout, guest and `POST` demo; `route:refresh:<client>`, **60 per minute** on refresh (:66). Over → 429; a throttle store error → **503** `unavailable` (fails closed). The web's own `AUTH_ROUTE_THROTTLE` and `authRouteThrottleKey` (`src/domain/identity/sign-in-throttle.ts:16-27`) already name `route:auth:<client>` with 10/min (stage 9b uses it for the password change).
- `requireProxySecret` (middleware.go:274-283): with a secret configured, guest and demo sign-in without the matching header → **403** 「この操作は Web からだけ利用できます。」. Its only purpose is "only the web's server may start these sessions"; once the web starts them itself, it has nothing to protect.

## 3. Tokens today

### Access token (auth/token.go)

- HS256 JWT, `AccessTTL` **15 min** (:13), `iss` `ffpf-zhuelog-api`, `aud` `["ffpf-zhuelog-mobile"]` (:21-22), `sub` = owner id, `iat`, `exp`; claims `role`, `login` (admin), `sv` (member) (`claims` :53-58, `Issue` :73-107).
- `Verify` (:111-146): HS256 only, issuer, audience, `exp` required, `iat` checked, `sub` non-empty; admin needs a non-empty `login`, member an `sv` ≥ 0, guest `sub == "guest"`; any other role refused. Every failure is `ErrUnauthorized`.
- The web verifies the same token itself: `verifyAccessToken` (`src/infrastructure/identity/access-token.ts:58-107`, 32-byte minimum secret :9).

### Refresh token (auth/session.go, store/refresh_tokens.go)

- `startSession` (session.go:185-207) on every sign-in: guests → `DeleteExpiredRefreshTokens("guest", now)` (store :193-201, `DELETE … WHERE "ownerId" = $1 AND "expiresAt" <= $2`); others → `PruneRefreshTokens(owner, now)` (store :176-188: the owner's expired rows, and revoked rows whose family has no live token). A prune error fails the sign-in (`TestLoginPruneErrorFailsLogin` login_test.go:113). Then `newPair` with a new 16-byte hex family id.
- `newPair` (:211-241): refresh token = **32 random bytes, unpadded base64url** (`refreshTokenBytes` service.go:17, `randomBytes` :154-159 = `crypto/rand`); TTL `RefreshTTL` **30 days**, guests `GuestRefreshTTL` **24 h** (token.go:14-17); the row keeps `ownerId`, `role`, `login` (admin), `sessionVersion` (member), `familyId`, `expiresAt`; only `hashRefreshToken` = **SHA-256, lowercase hex** (:260-263) is stored, in `ApiRefreshToken."tokenHash"` (unique).
- `Refresh` (:28-93): unknown → 401; revoked outside the 30 s grace (`RefreshReuseGrace` token.go:20) → revoke the family, 401 (theft); expired → 401; `checkCurrent` (§4) failing with 401/403 → revoke the family; otherwise rotate (`RotateRefreshToken` store :95-120, advisory lock on the family, conditional `UPDATE … WHERE "revokedAt" IS NULL`), or, for a just-rotated token within the grace, add a sibling (`InsertSiblingIfFamilyActive` :126-152). **Every successful refresh gives a new 30-day (24 h) token, so an active user is never signed out** (sliding expiry).
- `Logout` (:104-119): empty or unknown token → nil; otherwise `RevokeFamily` (store :156-170). The row stays (revoked) until a later prune.
- `ApiRefreshToken` (prisma/schema.prisma:108-122) has `@@index([familyId])`, `@@index([ownerId])`. No cron prunes it; only sign-ins of the same owner do.

## 4. Who is signed in (Go `Authenticate`, `Me`, `ActAs`; the web's copy)

- `requireAuth` (middleware.go:143-166): `Authorization: Bearer <token>` (scheme case-insensitive, one space, no second space) else 401; `Authenticate`; guest on a route without `allowGuest` → 403; with `X-Zhuelog-Act-As` → `actAs` (:177-194): not admin → 403 「他の人として操作できるのは管理者だけです。」; several headers or a value not matching `^password:[a-z0-9]{1,64}$` (`actAsOwnerIDPattern` :170) → 400; `ActAs` (auth/me.go:32-40: role admin and `ActorID == ""`, `findMember` :44-57 = `FindPasswordAccountByID`) not found → 404 「会員が見つかりません。」; logged `Info("acting as member", "actor", "owner", "path")`.
- `Authenticate` (session.go:125-134) = `Signer.Verify` then `checkCurrent` (:137-172):
  - admin: `Allowlist.Allows(ownerId)` (exact match, allowlist.go:30-33; parsed by `ParseAllowlist` :17-26 — split on `,`, trim, keep `^[0-9]+$`) else **`ErrForbidden`** (403);
  - member `password:<id>` → `SessionVersion(id)` (store/accounts.go:72-83), `ffpf:<sub>` → `FfpfSessionVersion(sub)` (store/ffpf_accounts.go:60-71), any other prefix → 401; not found → 401; a store error → 500; `current != sv` → 401;
  - guest: always fine; any other role → 401.
- `Me` (auth/me.go:61-107): admin → `{ownerId, role, login}` plus `actingAs {ownerId, loginId, displayName}` while acting; guest → `{ownerId: "guest", role: "guest", login: "guest"}` (`guestLogin` :12); FFPF member → `login` = the account's email, `displayName`; password member → `login` = loginId, `displayName`, `accountId`, `demo` (`isDemoAccount` auth/demo.go:50-52: hash `demo:no-password` or loginId = `DEMO_LOGIN_ID`); a missing account → 401.
- **The web does not call `Authenticate` or `/v1/me` to decide who is signed in** (stage 0). It does the same itself: `TokenCurrentUserProvider` (`src/infrastructure/identity/token-current-user-provider.ts:40-138`) reads `zl_access`, `verifyAccessToken`, then: admin not allowlisted → `{role: "revoked"}` (:71-72); admin with `zl_act_as` matching `ACT_AS_PATTERN` (:35, the same regex) and an existing `PasswordAccount` → `githubId` = the member, `actingAs`, `actorId`; malformed or missing → own id plus `actAsIgnored: true` (:78-96); member: `ffpf:`/`password:` account lookup and `sessionVersion` equality, else signed out (:99-130); `demo: true` like Go (:132-137); guest → `{githubLogin: "guest", role: "guest"}` (:56-58). `src/composition/current-user.ts:21-50` wraps it in React `cache()`. Tests: `tests/token-current-user-provider.test.ts` (15 tests, :67-240).
- The web still calls `/v1/me` in exactly one place: `startActingAsViaGo` (`src/infrastructure/go-api/go-api-session.ts:115-130`), to have Go confirm the member (`[400, 403, 404]` → not started) before writing `zl_act_as`.

## 5. Password sign-in (`LoginPassword`, auth/login.go:84-123)

In this order (`now` read once):

1. `consumeThrottle("client:" + client, 20)` (`maxAttemptsPerClient` service.go:26; window `throttleWindow` **15 min** :25) → over: `ErrThrottled` (no hashing, no lookup).
2. `NormalizeLoginID` (auth/validate.go:16-19: JS `trim()` then `toLowerCase()` via `jsstr`, then `^[a-z0-9._-]{3,32}$`); invalid id, empty password, or more than **128 runes** (`maxPasswordRunes` service.go:16) → `reject` = one `Simulate` on the first 128 runes (`truncateRunes` :164-173), `ErrUnauthorized`. Only the client key was counted.
3. `consumeThrottle("login:" + client + ":" + loginId, 5)` (`maxFailuresPerLogin` :27) → over: `ErrThrottled`.
4. `FindPasswordAccountByLoginID` (store/accounts.go:45-63): not found → `reject` (one `Simulate`), `ErrUnauthorized`; store error → wrapped error (500).
5. `Passwords.Verify(password, hash)`: an error (ctx done while waiting for a hashing slot) → 500; false → `ErrUnauthorized` **with no extra work** (the verify already cost one scrypt).
6. `ResetThrottle(loginKey)` (store/throttle.go:46-51); error → 500. The client key is **not** reset.
7. `startSession({ownerId: "password:" + id, role: member, sessionVersion})`.

- Every credential failure is exactly `ErrUnauthorized` after **exactly one** scrypt computation, and the hasher never sees more than 128 runes (`TestLoginPasswordFailuresAreUniform` login_test.go:247-298: short id `a`, `al ice`, 33×`a`, empty password, 129×`x`, 129×`パ` → only `client:` counted, no lookup; `nobody` and a wrong password → `client:` and `login:` counted, one lookup).
- `TestLoginPasswordClientLimitBlocksBeforeHashing` (:334-376): 20 attempts over different ids (every 4th malformed `x`), the 21st with the right password → throttled, no hash, no lookup, last consumed key `client:`; another client and the same client after 15 min succeed.
- `TestLoginPasswordLoginLimit` (:377-412): 5 wrong, the 6th (`ALICE`, right password) → throttled, no hash; another client and another id still work; after 15 min it works.
- `TestLoginPasswordSuccessResetsLoginCount` (:413-436), `TestLoginPasswordUnknownLoginIsThrottledLikeKnown` (:437-462: 5 attempts on `nobody` = 5 hashes, the 6th throttled; counts `client:` 6 and `login:` 6), `TestLoginPasswordThrottleStoreError` (:463), `TestLoginPasswordNormalizesLoginIDLikeJS` (:216), `TestLoginPasswordStoreErrorIsNotUnauthorized` (:300), `TestLoginPasswordHasherErrorIsNotUnauthorized` (:312).
- Throttle statements (store/throttle.go:15-43): prune at most 100 dead rows `FOR UPDATE SKIP LOCKED`, then one `INSERT … ON CONFLICT DO UPDATE … RETURNING "count"`; allowed while `count <= limit`. The web already runs the same two statements (`src/infrastructure/prisma/sign-in-throttle-store.ts:13-59`, stage 9b).
- Hasher (auth/password.go): parameters N=32768, r=8, p=1, 16-byte salt, 64-byte key (:17-24); `parseScryptHash` (:100-126) refuses anything the web could not have written (and `demo:no-password`, which costs **no** scrypt — so a demo login id answers faster; Go accepts that); `Verify` constant-time compare (:131-145); `Simulate` = `Verify` against a dummy hash of a random password (:149-153), built by `Warm` once (:158-168); at most **4** computations at once (`maxConcurrentHashes` :29, `acquire` :53-64). The web's `ScryptPasswordHasher` (`src/infrastructure/security/scrypt-password-hasher.ts:90-130`) has the same `verify`/`simulate`; its dummy hash is built lazily on the first `simulate` (so the first unknown-user sign-in of an instance costs one extra scrypt). Node runs `crypto.scrypt` on the libuv pool (4 threads by default), which bounds concurrency the same way. The format is pinned on both sides by `tests/fixtures/scrypt-golden.json`, written by Go's `TestScryptGolden` (auth/password_golden_test.go:140).

## 8. GitHub (`LoginGitHub` auth/login.go:17-31, auth/github.go, auth/github_apps.go)

- `GitHubApps.Exchange` (github_apps.go:14-21) picks the client whose `RedirectURI` equals the request's exactly (mobile or web), else `ErrUnauthorized` without calling GitHub.
- `GitHubClient.Exchange` (github.go:48-57): empty code or verifier, or a redirect URI other than its own → `ErrUnauthorized` (no call).
- `fetchToken` (:59-102): `POST https://github.com/login/oauth/access_token`, form `client_id`, `client_secret`, `code`, `code_verifier`, `redirect_uri`; `Content-Type: application/x-www-form-urlencoded`, `Accept: application/json`. Status ≠ 200 → unavailable; body not JSON → unavailable; `error` present → log `Warn("github token exchange rejected", "github_error", loggableOAuthErrorCode(error))` and `ErrUnauthorized`; no `access_token` → unavailable.
- `fetchUser` (:104-135): `GET https://api.github.com/user` with `Authorization: Bearer <token>`, `Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2022-11-28`; 401/403 → `ErrUnauthorized`; other non-2xx → unavailable; JSON with `id` > 0 (int64) and non-empty `login`, else unavailable.

Every failure is `ErrGitHubUnavailable` (502) or `ErrUnauthorized` (401), and never contains the code, verifier, secret or GitHub token (`TestExchangeErrorsOmitSecrets` github_test.go:411, `TestExchangeTokenErrorLogOmitsSecrets` :230).
- `loggableOAuthErrorCode` (auth/oauth_error.go:13-18): the code when it matches `^[a-z_]{1,64}$`, else `unrecognized`.
- `LoginGitHub`: owner id = decimal `user.ID`; not on the allowlist → **`ErrForbidden`** (403); else an admin session with `login` = `user.Login` (informational only; authorization uses the id). Tests login_test.go:16-112 (`TestLoginGitHubAllowsByIDWhateverTheLogin` :80), github_test.go:72-466 (`TestExchangeSuccess` :72 pins the form and headers above; `TestExchangeUnavailable` :259: token 500, malformed JSON, `{}`, closed server, user 500/404, malformed, id 0, id −5, empty login).
- The web: `signInWithGitHubViaGo` (go-api-session.ts:185-208) needs `AUTH_GITHUB_ID` (else `/signin?error=Configuration`), writes `zl_oauth` (§11.3) and redirects to `githubAuthorizeUrl` (`src/infrastructure/go-api/github-oauth.ts:100-114`: `client_id`, `redirect_uri`, `scope=read:user`, `state`, `code_challenge`, `code_challenge_method=S256`). The callback `GET /api/auth/callback/github/go` (`src/app/api/auth/callback/github/go/route.ts` → `handleGitHubCallback` `src/presentation/http/github-callback.ts:44-87`): `zl_oauth` cleared on every outcome; no `error` param, a parsable GitHub (no `provider`) cookie, `code`, `state` and `isSameState` (constant time, github-oauth.ts:94-98) → `loginGitHub(code, verifier, githubRedirectUri(publicOrigin(requestOrigin(headers))), clientIp)`; success → session cookies, `zl_act_as` cleared, **303** to `getSafeCallbackPath(saved.callbackPath)`; Go 403 → `/signin?error=AccessDenied`; anything else → `/signin?error=OAuthCallbackError`.

## 9. FFPF ID (`LoginFFPF` auth/login.go:40-68, auth/ffpf.go, store/ffpf_accounts.go)

`FFPFClient.Exchange` (ffpf.go:84-93): empty code, verifier or nonce, or a redirect URI other than its own → `ErrUnauthorized` without calling (`TestFFPFExchangeRejectsInputWithoutCalling` ffpf_test.go:452). 5. Key `kid` (§9 JWKS below): fetch failure → `ErrFFPFUnavailable`; kid not in the fresh JWKS → `kid`.
6. Signature: ES256 = ECDSA P-256 over SHA-256 of `header.claims`, signature exactly 64 bytes `r‖s` → else `signature` (another key; a 63-byte signature).
7. Claims JSON into `ffpfClaims` (:161-170): a field of the wrong JSON type → `claims` (`exp` as the string `"9999999999"`: `Exp` is `*float64`, not `NumericDate`, so a numeric string is refused).

10. `email_verified` is the JSON literal `true` (raw message compare :252) → else `email_verified` (`false`, `"true"`, missing).
11. `email` non-empty → else `email`.
12. `sub` matches `^[a-z0-9]{1,64}$` (`ffpfSub` :40) → else `sub` (`A/B`, `Cabc`, 65×`a`, missing).
