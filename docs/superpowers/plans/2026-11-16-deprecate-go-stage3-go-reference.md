## 0. Route and request limits

- Registration: `entryRoutes` router.go:298-303 → `r.private("POST /v1/imports/csv", importCSV(r.d.Entries, r.d.Now))`. `private` = requireAuth (guests 403 "このアカウントは利用できません。") + `rejectUserParam` (`?user=` → 400 invalid_request "リクエストが不正です。").
- **Not** `notForDemo`: the demo account may import (into its own notes; the nightly demo reset deletes them, store/demo.go:104-110).
- Act-as: honoured (no `notActing`). An admin acting as a member imports into the **member's** notes (Principal.OwnerID = member, middleware.go:141-210).
- Role check in handler: not admin/member → 403 forbidden "このアカウントは利用できません。" (import_handlers.go:52-58; unreachable today, defence in depth).
- Body limit: 4 MiB + 256 KiB for this route only (`maxCSVBodyBytes` import_handlers.go:23, applied in `limitBody` middleware.go:128-139; other routes 1 MiB middleware.go:18). Over → 413 too_large "リクエストが大きすぎます。" via `writeBodyError` respond.go:226-233.
- Timeout: after auth, read deadline now+4 min, write deadline now+4 min 10 s (`csvUploadTimeout` import_handlers.go:26-42). Server default 30 s elsewhere.
- Web side limits: `next.config.ts` `experimental.serverActions.bodySizeLimit: "4.5mb"`; the Go client waits up to 270 s for an upload (`UPLOAD_TIMEOUT_MS` src/infrastructure/go-api/client.ts:45-46).

## 1. Handler order (import_handlers.go:46-105) — first failure wins

| #   | Check                                                             | Status / code                                                                | Message (exact)                                                                      |
| --- | ----------------------------------------------------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 1   | not multipart (`r.MultipartReader` fails)                         | 400 invalid_request                                                          | リクエストが不正です。                                                               |
| 2   | no `csvFile` part, part without filename (text field), or 0 bytes | 400 invalid_request                                                          | CSVファイルを選択してください。 (msgSelectCSVFile respond.go:51)                     |
| 3   | file > 4 MiB (4,194,304 bytes; exactly 4 MiB passes)              | 413 too_large                                                                | ファイルは4MB以下にしてください。 (msgCSVFileTooLarge respond.go:52)                 |
| 4   | other multipart read error                                        | 413 if MaxBytesError else 400 generic                                        | —                                                                                    |
| 5   | `!strings.HasSuffix(strings.ToLower(name), ".csv")`               | 400 invalid_request                                                          | 拡張子が.csvのファイルを選択してください。 (msgCSVExtension respond.go:53)           |
| 6   | `csvimport.Parse` ValidationError                                 | 400 invalid_csv (respond.go:85)                                              | the parser's message, §2                                                             |
| 7   | `csvimport.FileName` (NUL in name)                                | 400 invalid_csv                                                              | CSVの形式を確認してください。引用符が閉じていないか、1行が長すぎる可能性があります。 |
| 8   | `CreateImportBatch` error                                         | 500 internal                                                                 | サーバーでエラーが発生しました。                                                     |
| ok  |                                                                   | **201** `{"batch":{"id","importedAt":"YYYY-MM-DDTHH:MM:SS.sssZ"},"count":N}` |                                                                                      |

- `readCSVFile` (import_handlers.go:112-143): uses the **first** part named `csvFile`; other parts are skipped; reads at most 4 MiB + 1 byte. Size is checked before the extension (test "over 4 MiB and not csv: size first").
- Extension check is on the raw multipart filename (case-insensitive, `.CSV` OK; `a.csv.txt`, `acsv` rejected).
- CSV contents are never logged (TestImportCSVHandlerNeverLogsContents import_handlers_test.go:261).
- No AI, no rate limit, no AiUsage.

## 2. Parsing rules (csvimport/parse.go)

Constants (parse.go:29-39): `maxRows 1000`, `maxCellUnits 10_000` (UTF-16 units = JS `length`), `maxColumns 103` (3 + 100 hints), `maxRecordSize 100_000`, `maxFileName 255`.

Messages (exact):

- `msgFormat` = `CSVの形式を確認してください。引用符が閉じていないか、1行が長すぎる可能性があります。`
- `msgNoData` = `CSVにデータ行がありません。`
- `msgTooManyRows` = `一度にインポートできるのは1000件までです。`
- `{n}行目は3列未満です。`
- `{n}行目は上限（各項目1万文字・ヒント100列）を超えています。`
- `{n}行目の「最初の文」「添削後の文」「ピンイン」は必須です。`

Steps of `Parse` (parse.go:45-110):

1. Decode like `File.text()`: drop one UTF-8 BOM, replace invalid UTF-8 (WHATWG: one U+FFFD per maximal invalid subsequence, parse.go:193-245); then csv-parse's `bom` drops **one more** BOM (parse.go:50-52; fixture double_bom.csv).
2. Read records = csv-parse with `{ bom: true, skip_empty_lines: true, relax_column_count: true, trim: true, max_record_size: 100_000, to: 1002 }` (parse.go:1-3, 247-380):
   - delimiter `,`, quote and escape `"` (`""` inside quotes = `"`), record delimiter auto-detected at the first line break among `\r\n`, `\n`, `\r` and then fixed (crlf_then_lf.csv, cr_only.csv).
   - trim = ECMAScript WhiteSpace+LineTerminator (`jsstr.IsSpace`: \t \n \v \f \r space U+00A0 U+1680 U+2000-200A U+2028 U+2029 U+202F U+205F U+3000 U+FEFF) on both sides of unquoted fields; quoted fields keep inner spaces; only trimmable chars may follow a closing quote.
   - empty lines skipped (but a line holding only `""` is a record).
   - stops after 1002 records (enough to detect "1001 data rows after a header").
   - any csv-parse error (unclosed quote, invalid opening/closing quote, non-trimmable char after closing quote, record over 100,000 UTF-16 units) → `msgFormat`.
3. 0 records → `msgNoData`.
4. Header = first record has ≥3 cells and each of the first three, after `trim`, removing ASCII spaces `" "` and lowercasing, is in (parse.go:131-157):
   - col 1: `最初の文` `原文` `original`
   - col 2: `添削後の文` `添削文` `corrected`
   - col 3: `ピンイン` `ピン音` `拼音` `pinyin` (`ピンイン` was added in Go after the web parser; the export writes it)
     Header → skipped (offset 1). Only the first record can be a header.
5. No rows left → `msgNoData`. More than 1000 rows → `msgTooManyRows` (checked before any row check).
6. Per row, in order (row number `n` = record index + offset + 1, i.e. counts records, not physical lines; header is row 1; blank lines do not count, a multi-line quoted record counts once — blank_line_numbering.csv):
   - `< 3` cells → `{n}行目は3列未満です。`
   - `> 103` cells or any cell `> 10,000` UTF-16 units (before the extra trim) → `{n}行目は上限…`
   - every cell trimmed again with JS `trim()`; any of the first three empty → `{n}行目の…必須です。` (full-width space U+3000 counts as empty: empty_required_fullwidth.csv)
   - hints = cells 4.. that are non-empty after trim, in order (empty hint cells dropped, positions close up)
   - first failing row stops everything; nothing is stored.
7. After all rows pass: any NUL (U+0000) in any stored text or hint → `msgFormat` (Go addition; Postgres cannot store NUL; the old web failed only on save). Row errors win over NUL (TestParseRejectsNUL parse_test.go:187).
8. Every draft is `kind: "correction"`.

`FileName(name)` (parse.go:121-129): NUL → `msgFormat`; else decode as UTF-8 and keep the first 255 UTF-16 code units (JS `name.slice(0, 255)`; a cut surrogate pair becomes U+FFFD, as JS would store it).

## 3. Storing (store/entries.go:175-219)

`CreateImportBatch(ctx, ownerID, fileName, drafts, now)` = one transaction (`pgx.BeginFunc`) running `queueImportBatch` + `execBatch`:

- `now = dbTime(now)` (UTC, truncated to ms, entries.go:63-66).
- `ImportBatch`: `id = newID()` ("c" + 24 of a-z0-9, store/store.go:133), `fileName`, `rowCount = len(drafts)`, `importedAt = now`.
- `LearningEntry` i (0-based, input order): `id = newID()`, `kind = "correction"`, texts, `createdAt = now + i ms`, `ownerId`, `batchId`. `deletedAt`/`sharedAt` NULL. Rationale (entries.go:176-178): `(createdAt, id)` order follows the input order.
- `Hint`: `id = newID()`, `content`, `position = 0..` among the kept hints, `learningEntryId`. Unique `(learningEntryId, position)` (prisma/schema.prisma:47).
- Any error → whole transaction rolled back (TestCreateImportBatchRollsBack store/entries_test.go:138) → 500.
- No ReviewItem is created (notes enter the review queue only by the review toggle).
- Worst case: 1000 entries × 100 hints = 100,000 Hint rows in one transaction (all pgx batch statements, one per row).
