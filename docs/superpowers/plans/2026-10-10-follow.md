# フォロー・フォロワーと学習ノートの共有 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 管理者とメンバーがほかのメンバーをフォローし、その人が共有した学習ノートを `/follow` のタイムラインで読めるようにする。

**Architecture:** `LearningEntry` に `sharedAt DateTime?`、新しく `Follow` テーブルを足す。core に `FollowRepository` と4つの use case（フォロー・解除・ディレクトリ・タイムライン）と `ShareLearningEntry` を置き、Prisma で実装する。書き込みは `follow-controller.ts`（依存を引数で受ける）→ `follow-actions.ts`（Server Action：再検証）→ 既存の `NoteActionForm`。

**Tech Stack:** Next.js 16.3.8（Server Actions、`useActionState`）、Prisma 7 + PostgreSQL、zod 4、node:test + tsx、Playwright。

**Spec:** ../specs/2026-10-10-follow-design.md

## Global Constraints

- 持ち主ID・フォローする人は常に `user.githubId`（`getCurrentMemberUser()`）。フォームから持ち主ID・フォローする人は受け取らない。
- フォローされる人のID検証：`/^password:[a-z0-9]{1,64}$/`。学習ノートのID検証：`/^[a-z0-9]{1,64}$/`。不正な値は「見つからない」と同じ扱い。
- 文言（そのまま使う）：
  - ヘッダーのリンク：「フォロー」
  - 見出し：「フォロー」、件数：「フォロー中 N人・フォロワー N人」
  - 節の見出し：「メンバー」「フォロー中の人の共有ノート」
  - ボタン：「フォローする」「フォロー解除」「共有する」「共有をやめる」
  - バッジ：「フォローされています」「共有中（フォロワーが見られます）」
  - 空の表示：「ほかのメンバーはいません。」「共有されたノートはまだありません。」
  - タイムラインの見出し行：「〇〇さん・<登録日時>」（日時は `formatTokyoDateTime`）
  - 権限なし：「ログインし直してください。」
  - 対象なし：「見つかりませんでした。画面を更新してください。」
  - 自分をフォロー：「自分はフォローできません。」
  - DB失敗：「処理できませんでした。時間をおいてもう一度お試しください。」
- タイムラインの上限：100 件（`FOLLOW_TIMELINE_LIMIT`）。
- ログには固定コード `FOLLOW_FAILED`・`SHARE_FAILED` だけを出す。名前・本文は出さない。
- マイグレーション名：`add_follows_and_shared_notes`。
- 依存パッケージは追加しない。本番DBへの適用とマージはこの作業では行わない。

## Review Focus

1. 細工した POST でフォームに存在しないメンバーや管理者の数字IDを入れる → 何も保存せず「見つかりませんでした。…」（Task 2 と Task 3 のテスト）。
2. 管理者が細工した POST で共有を切り替える → 拒否し、ノートは変わらない（Task 3 のテスト）。
3. 共有中のノートをゴミ箱に入れる → フォロワーのタイムラインから消える（Task 4 の E2E）。
4. だれもフォローしていない → DB を読まずに空のタイムライン（Task 2 のテスト）。
5. 同じ人を2回フォロー（ダブルクリック） → 1件のまま、エラーにしない（Task 2：Prisma 実装は `createMany` の `skipDuplicates: true`、Task 4 の E2E でボタンが「フォロー解除」になることを確認）。

- [ ] **Step 3: スキーマとマイグレーションを足す**

- [ ] **Step 4: 型・リポジトリ・use case を実装する**

- mapper の入力型に `sharedAt: Date | null` を足し、そのまま返す。
- `setShared`：`shared` が `true` なら `updateMany({ where: { id, ownerId, deletedAt: null, sharedAt: null }, data: { sharedAt: new Date() } })`。0件なら `count({ where: { id, ownerId, deletedAt: null } }) === 1` を返す。`false` なら `updateMany({ where: { id, ownerId, deletedAt: null }, data: { sharedAt: null } })` の `count === 1`。

- インターフェースのコメントに「共有中の判定・ゴミ箱の除外」を1行ずつ書く。
- 既存の fake と `LearningEntry` を組み立てるテストを直す（fake は `unused`、エントリは `sharedAt: null`）。

- [ ] **Step 3: 実装する**

- `FollowMember`：`followeeId === followerId` → `"self"`。`followeeId` が `password:` で始まらない、または `accounts.findById(<残り>)` が null → `"not-found"`。それ以外は `follows.follow` して `"followed"`。
- `ListFollowDirectory`：`accounts.list()`、`listFollowing(viewerId)`、`listFollowers(viewerId)` を並行に読む。`followingCount` は `members` のうち `following` の数、`followerCount` は `listFollowers` の長さ。
- `ListFollowTimeline`：`listFollowing` が空なら `[]`。表示名は `accounts.list()` から `ownerIdForAccount(id) → displayName` の Map。
- Prisma：`follow` は `createMany({ data: [{ followerId, followeeId }], skipDuplicates: true })`、`unfollow` は `deleteMany(...).count === 1`、一覧は `findMany` の `select` で ID だけ。
- `social-container.ts` は `learning-container.ts` と同じ形。アカウントは `password-account-services` の `passwordAccountRepository` を使う。
