# セキュリティレビュー（2026-09-24）

対象: v0.4.0からv0.4.1。アプリの認証・認可、全APIとServer Action、CSV・学習ログ、個人添削、管理者チャット、LINE webhook/worker、DB接続、ブラウザー保存、配布物、依存関係を確認した。これはコードレビューと回帰試験であり、第三者による侵入試験や安全性の保証ではない。

## 確認事項と修正

| 内容                                                            | 評価                                                          | 対応                                                                                                    |
| --------------------------------------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `src/app` に対してルートの `proxy.ts` が読み込まれていなかった  | 多層防御の欠落。既存の各画面・API・Actionの認可は機能していた | `src/proxy.ts` に移動し、未認証ページ/APIの拒否を実ブラウザーで検証                                     |
| 許可リストから削除された管理者の既存JWTが権限を保持             | 認可の不備                                                    | セッション読み取り時に現在の許可リストを再確認。失効済み管理者の画面/API/古いフォームを拒否             |
| CSV保存失敗時に例外の詳細を返し、記録していた                   | 内部情報・入力内容の漏えいリスク                              | 意図した入力検証エラーのみ返し、その他は汎用文言。DB/トップページ/AIの生エラーログを抑制                |
| CSPがスクリプト・通信先を制限していなかった                     | XSSに対する防御強化（既存のXSS成立は確認されず）              | nonce・strict-dynamic、インラインイベント禁止、同一オリジン通信、フレーム埋込禁止。ページは動的生成     |
| 管理者チャットの本文読み込み・AI待機時間に明示的上限がなかった  | リソース消費・意図しない再試行のリスク                        | 256KiB/読み取り10秒、同一オリジン/JSON検証、AI45秒/再試行0。個人添削/LINEも共通の制限付き読み取りを利用 |
| CSVの行数以外の列・項目・レコード長制限が不十分                 | 大きな入力による負荷                                          | 1,000行、各項目1万文字、1行10万文字、ヒント100列。全体5MiB制限も維持                                    |
| 非常に大きなノート番号をDBに渡せた                              | 不正入力・不要な検索負荷                                      | 整数範囲を検証し、その日の件数を超える場合はOFFSET検索しない                                            |

| ローカルCodexの動的実行ファイル指定が広範囲のファイル追跡を誘発 | 秘密ファイルの配布物混入リスク                                | Turbopackの追跡対象外を明示、env/秘密seed等をビルドトレースから除外                                     |

Server ActionはProxyのHTMLリダイレクトではなく、Action内部の認可で拒否する。`next-action` ヘッダーはプロトコル判定にしか用いず、権限を付与しない。

## 検証

- 型チェック・Lint・本番ビルド。ビルド出力に `Proxy (Middleware)` が存在し、従来のCodex広範囲追跡の警告が消えた。
- 単体テスト40件。権限失効、callback、TLS、CSP、読み取り上限/タイムアウト、CSV上限/エラー秘匿、チャット検証を含む。
- PC/モバイルのE2E52件。署名付きLINE処理、CSV、ゲスト制限、BYOKのDB非保存、CSPによる悪意あるHTMLスクリプトの拒否、権限失効、Cookie属性を含む。
- `npm audit`: 既知の脆弱性0件（確認時点）。GitHub CodeQLもリリース対象のコミットで確認する。
- Git全履歴の高確度な秘密鍵/APIトークン形式と、ローカル環境の秘密値との一致を確認。検出された一致は公開サンプルと同じループバック開発DB接続文字列のみ。実際のリモートDB/API秘密値の一致なし。汎用的な全秘密情報の発見を保証するものではない。
- 18個のビルドトレース内にenv・private seed・`.vercel`の混入なし。秘密ファイルはGit/Vercel送信対象からも除外。
- 外部AIの成功応答はモックで検証。試験で実際のOpenAI課金は発生させず、本番学習データを変更しない。

## 維持した境界・残る制約

- 共有ノートはゲストにも公開される設計。機密情報を書き込まない。ゲストの共有DB書き込み・管理者チャット・LINE利用は禁止。
- BYOKのキーは画面メモリにのみ保持し、サーバー経由でOpenAIへ送る。ブラウザー/DB/ログへ保存せず、管理者キーにフォールバックしない。履歴は端末のlocalStorageに平文保存されるため、共有端末では削除が必要。
- BYOKのレート制限はプロセス内。サーバーレスの複数インスタンスをまたぐ厳密な課金上限やDDoS防御ではない。OpenAI側の利用枠・キー失効、Vercel側の利用状況確認が別途必要。
- LINEはHMAC、送信者/宛先、時刻、イベント重複、ジョブリース、再送回数を検証。MacのCodex経路は管理者専用・外向きポーリング・子プロセスへのアプリ秘密値引き継ぎ禁止を維持。
- クラウドアカウント全体の権限、Mac/ブラウザー拡張、ホスティング事業者内部、未公表の脆弱性はこのコード監査の保証範囲外。環境変数・キーのローテーションや将来の依存関係更新も継続して必要。
