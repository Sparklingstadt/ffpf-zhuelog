# v0.34.0 — ログインを Better Auth に替える

Sparklingstadt ID と typle-r に合わせて、自前のログイン（GitHub・`zl_session`・`PasswordAccount`・`SidAccount`）を Better Auth 1.7.28 に替えました。データの持ち主も、Better Auth の `user` にそろえました。設計は `docs/superpowers/specs/2026-11-27-better-auth-migration-design.md` にあります。

**ログイン**

- 切り替えのとき、全員が一度ログアウトになります。ID とパスワードの会員は、同じパスワードで入り直せます（ハッシュは同じ scrypt のまま移します）。
- 管理者は、GitHub ではなく Sparklingstadt ID でログインします。管理者は `user.role` が `admin` の人で、環境変数の許可リストはなくなりました。
- 会員は、ログイン ID でだけログインします。メールアドレスでのログインは閉じています。
- ログインの試行回数は、Better Auth のレート制限（DB の `rateLimit`）で数えます。

**管理者の機能**

- 会員の作成・パスワードの再設定・なりすましは、Better Auth の `admin` プラグインが行います。画面は同じ `/admin/accounts` です。
- なりすましの間は、会員としてログインしているのと同じです。管理画面は使えず、AI の利用量は会員のほうに数えます。なりすまし中は、パスワードの変更と LINE の連携を使えません。
- 会員の一覧は、100 人を超えても全員を出します。

**デモとゲスト**

- 「デモで試す」は、`DEMO_PASSWORD` でデモのアカウントにログインします。毎晩のリセットが、パスワードを入れ直します。
- 毎晩のリセットが、作ってから 24 時間たったゲストを消します。
- デモは全員で 1 つのアカウントなので、Better Auth のセッションの一覧と取り消しのルートを閉じました。ほかに使わないルート（名前の変更、ログイン ID の有無の確認、ID サーバーのトークンを渡すルート）も閉じています（`docs/architecture.md` の「4. 認証」）。

**デプロイ前に必要な作業**

マイグレーションが古い表と `ownerId` の列を落とすので、**マイグレーションが当たってから本番が切り替わるまで、本番は止まります**。また、**前のデプロイには戻せません**。`docs/deployment.md` の末尾の「移行の記録」の「Better Auth への切り替え（2026 年 11 月）」の手順 1〜4 を、この順に済ませてください。

1. Sparklingstadt ID のクライアントに、`post_logout_redirect_uri`（`<AUTH_URL の origin>/signin`）があることを確かめます。
2. Vercel の Production に `BETTER_AUTH_SECRET` と `DEMO_PASSWORD` を入れます（Preview にも `BETTER_AUTH_SECRET`）。
3. 本番から切った Neon のブランチで、`auth:prepare-admin` とマイグレーションを一度流して確かめます。
4. 本番の DB で `auth:prepare-admin` を `--check-only` で流して `OK` を確かめ、それから `--check-only` を外して流します。
5. 利用の少ない時間に、止まる時間の枠を取ります。マージしたら、そのコミットの本番のビルドが Ready になったところで、`verify` を待たずに `deploy` を手で起動します（手順 5）。

**デプロイ後に必要な作業**

同じ「Better Auth への切り替え」の手順 6〜8 です。

1. `/api/cron/demo-reset` を 1 回呼び、デモのパスワードを入れます。
2. 管理者が Sparklingstadt ID でログインして管理画面を開けること、会員の 1 人が ID とパスワードでログインしてノートが見えることを確かめてください。
3. GitHub の OAuth App を消し、Vercel から `AUTH_GITHUB_ID`・`GITHUB_WEB_CLIENT_SECRET`・`AUTH_ALLOWED_GITHUB_IDS`（あれば `AUTH_SECRET`・`AUTH_GITHUB_SECRET`）を消します。

- 型チェック、Lint
- マイグレーションのテスト（`pnpm run test:migration`）
- ブラウザー E2E（全件。Better Auth のログイン・管理者の機能・なりすまし・デモ・閉じたルートを確かめます）
