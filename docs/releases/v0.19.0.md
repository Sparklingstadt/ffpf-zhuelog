# v0.19.0 — WebのログインとデータをGo API経由にする

Web（Next.js）のログインと学習ノートの読み書きを、すべてGo API経由にしました。WebはAuth.js（`next-auth`）とPrismaの読み書きを外し、フロントエンドだけになります。画面の見た目と使い方は変わりません。ただし、**全員がログインし直しになります**。

- Webのログイン・ログアウト・GitHubログイン・ゲストログイン・トークンの更新を、Go APIで行います（#84）。ログインの状態は、Cookie（`zl_access`・`zl_refresh`・`zl_oauth`）に持ちます。
- Webの学習ノート・ゴミ箱・共有・フォロー・CSVインポート・会員の管理・パスワード変更の読み書きを、Go API経由にしました（#85）。CSVの解析もGo側で行います。
- Go APIの `GET /v1/entries` と `GET /v1/trash` の応答に、全体の件数 `total` を足しました（項目が増えるだけです）。
- Go APIに、ゲストのトークンを発行する `POST /v1/auth/guest` と、今の利用者を返す `GET /v1/me` を足しました。同時のリフレッシュは、ローテーションから30秒以内なら失効させずに通します。
- Webの実行とビルドに `DATABASE_URL` が要らなくなりました。`GO_API_URL` が `https://` でもローカルでもないときは、トークンも秘密も送りません。
- Go APIのVercelプロジェクト（`ffpf-zhuelog-api`）を作るときの注意点を、手順書に足しました（#86）。ドキュメントだけの変更です。
- DBのスキーマは変えていません。マイグレーションはありません。

**デプロイ前に必要な作業**

この版をマージすると、Go APIがないとWebは動きません。**マージの前に** 次を済ませてください（詳しくは `docs/api-deployment.md` の「段階3のマージの前に行うこと」）。

1. Go APIのVercelプロジェクト（Root Directory は `services/api`）を作り、`/health` が `200` を返すことを確認してください。作るときは、Vercel Authentication を外します。環境変数は、`DATABASE_URL`、`API_JWT_SECRET`、`AUTH_ALLOWED_GITHUB_IDS`、`GITHUB_MOBILE_*`（モバイル用のOAuth Appがなければ仮の値で起動できます）、`GOFLAGS=-buildvcs=false` です。Productionとして、Previewとは別のDB・別の鍵を使ってください。
2. Go APIに `GITHUB_WEB_CLIENT_ID`・`GITHUB_WEB_CLIENT_SECRET`・`GITHUB_WEB_REDIRECT_URI`（`https://<Webのホスト>/api/auth/callback/github/go`）・`API_WEB_PROXY_SECRET` を入れて、再デプロイしてください。`GITHUB_WEB_CLIENT_SECRET` は読み戻せないので、GitHubのOAuth Appで新しく作ります。古いSecretは、Auth.jsが使っているあいだは消さないでください。
3. 本番のWebのVercelプロジェクトに、次の4つを入れて再デプロイしてください。この版より前のmainのWebは、`GO_API_URL` があるとログインをGo APIで行います。
   - `GO_API_URL`: Go APIのURL（`https://`、末尾の `/` なし）
   - `API_WEB_PROXY_SECRET`: Go APIと同じ値（32バイト以上）
   - `AUTH_URL`: Webの公開origin
   - `AUTH_GITHUB_ID`: `GITHUB_WEB_CLIENT_ID` と同じOAuth AppのClient ID
4. 本番のWebで、GitHub・パスワード・ゲストのログインとログアウトができることを確認してください。切り替えるとAuth.jsのCookieは使われなくなるため、**全員が一度ログインし直しになります**。
5. 確認できたら、マージしてください。

`DATABASE_URL`・`AUTH_SECRET`・`AUTH_GITHUB_SECRET`・`AUTH_ALLOWED_GITHUB_IDS` は、この版が本番で問題なく動くまで、Webに残しておいてください（戻すときに使います）。

**デプロイ後に必要な作業**

1. 動作を確認したら、Webの `AUTH_SECRET`・`AUTH_GITHUB_SECRET`・`AUTH_ALLOWED_GITHUB_IDS` は不要になります。`DATABASE_URL` も実行には要りませんが、マイグレーションのために `vercel env pull` で取るなら残してください。
2. 戻すときは、この版のマージを revert してWebを再デプロイしてください。revertしたWebは学習ノートをDBから直接読み書きするので、`DATABASE_URL` が要ります。Auth.jsのログインまで戻すなら、さらにWebから `GO_API_URL` を消して再デプロイしてください（`AUTH_SECRET`・`AUTH_GITHUB_SECRET`・`AUTH_ALLOWED_GITHUB_IDS` も要り、全員がもう一度ログインし直しになります）。
