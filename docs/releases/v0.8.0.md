# v0.8.0 — LINE添削の失敗通知とテスト並列化

MacのCodex更新後も、Go workerはバージョン一致で停止せず、実際に添削を試すようになりました。添削が失敗した場合は、原因の説明とエラーコードをLINEへ通知します。

- 失敗通知は既存のジョブへ保存してから配送し、lease・再送キー・配送期限による重複防止を維持します。
- 失敗した添削では学習ノートを作成しません。生成は自動再試行せず、復旧後に本人が文を再送します。
- Macとサーバーのログに日時・ジョブID・原因コードを記録します。入力文・秘密情報・生のプロバイダーエラーは通知やエラーログに含めません。
- Businessログイン、固定モデル、読み取り専用、ツール禁止、タイムアウト、回答形式の検証は維持します。
- GoとTypeScriptのテスト群を同時実行し、それぞれ独立したテストを最大4並列で実行します。共有環境変数を変更するテストと共有DBを初期化するE2Eは直列です。

DBマイグレーションと環境変数の追加はありません。Web/APIを先に更新してから、ビルドしたGo workerをLaunchAgentで再起動します。旧APIへの失敗報告も継続できる互換処理を備えています。

Macの停止・スリープ中や通信断では即時通知できません。今回のバージョン制限撤廃はGo workerが対象で、別機能のローカルWebチャットは変更していません。

検証: Go vet・race detector、TypeScript単体テスト70件、LINE失敗通知のDB保存・古いleaseの拒否・通知配送の再試行、ブラウザーE2E、型チェック、Lint、Turbopack本番ビルド、実機Codexでの添削。
