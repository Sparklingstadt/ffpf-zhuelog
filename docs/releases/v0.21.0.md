# v0.21.0 — FFPF IDでログインできるようにする

FFPF ID（ffpf-portal が提供する OpenID Connect のログイン）で、メンバーとしてログインできるようにしました。ログイン画面に「FFPF IDでログイン」を足しています。FFPF IDでログインした人も、パスワードのメンバーと同じく学習ノート・共有・フォロー・タイムライン・LINE連携を使えます。

- ログイン画面に「FFPF IDでログイン」を足しました。WebとGo APIの両方にFFPF IDの設定があるときだけ表示します。
- Go APIに `POST /v1/auth/ffpf` を足しました。本文は `{ code, codeVerifier, redirectUri, nonce }` で、GitHubのログインと同じトークン一式を返します。portal で認可コードを交換し（client_secret_basic、10秒、リダイレクトには従いません）、IDトークンを portal の JWKS（10分キャッシュ）で検証します（ES256・`iss`・`aud`・`exp`・`nonce`・`email_verified`）。
- FFPF IDの人の持ち主のIDは `ffpf:<sub>` です。新しい表 `FfpfAccount` に、メールアドレスと表示名を保存し、ログインのたびに更新します。メールアドレスは表示用で、許可の判定には使いません。許可リストは無く、メールアドレスを確認済みのFFPF IDなら誰でもメンバーになれます。
- メンバー一覧にFFPF IDの人も出るようにしました。パスワードのメンバーとFFPF IDの人は、お互いにフォローでき、共有したノートがタイムラインに出ます。
- FFPF IDの人にはこのサービスのパスワードが無いので、「パスワード変更」（`/account/password`）には FFPF ID のマイページへのリンクを出します。`POST /v1/account/password` は `403` です。
- 誤りのとき、Webは「認証サービスからの結果を確認できませんでした。」と出してログイン画面に戻します。Go APIは、入力・交換・検証の失敗に `401`、portal に届かないときに `502 ffpf_unavailable`、設定が無いときに `503` を返します。
- ドキュメント（`docs/api-deployment.md` の「9. FFPF ID でのログイン」、VuePress の認証のガイドとリファレンス、エラーの一覧）に、新しい環境変数とルート、portal へのクライアントの登録の手順を書きました。

**デプロイ前に必要な作業**

1. ffpf-portal で `pnpm run oidc:client zhuelog` を実行し、出てきたJSONの `redirectUris` に `https://ffpf-zhuelog.vercel.app/api/auth/callback/ffpf` を入れて、portal の `FFPF_OIDC_CLIENTS` に足し、portal を再デプロイしてください（手順は ffpf-portal の README）。`secret=` の値は、下の Go API の `FFPF_ID_CLIENT_SECRET` に使います。
2. マイグレーション `20261027120000_add_ffpf_accounts` を本番DB（Neon）に適用してください。デプロイより先に行います。`FfpfAccount` の表を追加するだけです。
3. Go APIのVercelプロジェクトの Production に、`FFPF_ID_ISSUER`（portal の issuer）・`FFPF_ID_CLIENT_ID`（`zhuelog`）・`FFPF_ID_CLIENT_SECRET`・`FFPF_ID_REDIRECT_URI`（`https://ffpf-zhuelog.vercel.app/api/auth/callback/ffpf`）を入れてください。4つはすべて設定するかすべて空にします（一部だけだと起動時に止まります）。
4. WebのVercelプロジェクトに、`FFPF_ID_ISSUER`・`FFPF_ID_CLIENT_ID`（Go APIと同じ値）を入れてください。Client Secret はWebには入れません。

**デプロイ後に必要な作業**

1. **Go APIに、mainを手動でデプロイしてください。** Go APIのVercelプロジェクトは、Gitからの自動デプロイが切れているので、マージしてもデプロイされません（v0.20.0 と同じ手順です。Deployments の Redeploy は使いません）。
2. `curl -i -X POST https://ffpf-zhuelog-api.vercel.app/v1/auth/ffpf -H 'content-type: application/json' -d '{"code":"x","codeVerifier":"x","redirectUri":"x","nonce":"x"}'` が `401`（`503` ではない）を返すことを確認してください。
3. 本番のWebで、FFPF IDでのログイン、ノートの追加、メンバー一覧、ログアウトを試してください。
4. Webの本番のURLが付いたかを確認してください（付かないときは、v0.20.0 と同じくデプロイを手で Promote します）。

検証: Goの全テスト（`go test -race`、実際のPostgresを使うテストを含む）、TypeScript単体テスト、ブラウザーE2E、型チェック、Lint。E2Eでは、`e2e/fixtures/ffpf-oidc-stub.ts` の小さなOIDCスタブを issuer にして、ボタンからログイン・ノートの追加・メンバー一覧とフォロー・`/account/password` のリンク・ログアウトまでを確かめています。本物の portal には接続していません。
