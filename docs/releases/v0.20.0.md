# v0.20.0 — LINEの添削・翻訳をGo APIで作り直す

v0.17.0 で外したLINEの添削・翻訳を、Go API の上に作り直しました。以前は1人だけでしたが、今回は会員と管理者がそれぞれ、自分のLINEを連携コードで結びつけて使えます。あわせて、CSVのインポートとエクスポートの画面、トップバーのGitHubリンク、Go APIのログイン不具合の修正を含みます。

- LINEに送った文を、OpenAI（`gpt-5-mini`）で添削・翻訳して返信し、送った人の学習ノートに追加します。漢字だけの文は添削、ひらがな・カタカナを含む文は中国語訳です。ノートはバッチ名 `LINE` で保存します。500文字を超える文は処理しません。
- 連携は Webの「LINE連携」（`/account/line`）で行います。連携コード（8文字、10分間有効）を出してLINEに送ると、そのLINEとアカウントが結びつき、同じ画面で解除できます。ヘッダーに「LINE連携」を足しました（会員と管理者だけ。ゲストは使えません）。
- 処理は webhook の中で行います。間に合わなかった文は保存だけして「時間がかかっています」と返し、毎朝6時（日本時間）のCronが1回だけ試し直して、結果をpushで返します。pushはLINEの無料プランの月200通の枠を使います。
- LINEの設定（`LINE_CHANNEL_SECRET`・`LINE_CHANNEL_ACCESS_TOKEN`・`OPENAI_API_KEY`）が空のGo APIでは、LINEのルートは404になり、「LINE連携は今は使えません。」と表示します。
- CSVのインポートを専用の画面 `/import` に移しました。ホームには「CSVをインポート」「CSVでエクスポート」のボタンを置いています（#88）。
- 学習ノートを選んで、CSVでダウンロードする画面 `/export` を追加しました。インポートと同じ形式（BOM付きUTF-8）なので、書き出したファイルをそのまま取り込み直せます。対象は本人のノートだけで、最大10,000件まで読み込みます。
- トップバーに、GitHubのリポジトリへのリンクを足しました。ログイン前の画面にも出ます（#90）。
- Go APIのDB接続で、Neonのプール接続のときにprepared statementの名前がぶつかり、ID・パスワードのログインが500になることがあった問題を直しました（#87）。
- `ip-address` を 10.7.4 に更新しました（CIの `pnpm audit` が新しい勧告で落ちるため）。

**デプロイ前に必要な作業**

1. マイグレーション `20261023090000_add_line_link` を本番DB（Neon）に適用してください。デプロイより先に行います。`LineLink`・`LineLinkCode`・`LineMessage` の3つのテーブルを追加するだけです。
2. Go APIのVercelプロジェクトの Production に、`LINE_CHANNEL_SECRET`・`LINE_CHANNEL_ACCESS_TOKEN`・`OPENAI_API_KEY`・`CRON_SECRET` を入れてください。LINEの3つの値は、すべて設定するかすべて空にします（一部だけだと起動時に止まります）。`CRON_SECRET` が空のときは、拾い直しのルートは常に401を返します。
3. WebのVercelプロジェクトに、`LINE_ADD_FRIEND_URL`（LINE公式アカウントの友だち追加リンク。`https://` で始まるものだけ使います。空なら画面に出しません）を入れてください。
4. LINE Developers で、Messaging APIのWebhook URLを `https://ffpf-zhuelog-api.vercel.app/v1/line/webhook` にして、Webhookの利用をオンにし、「応答メッセージ」をオフにしてください（オンのままだと、LINEの自動応答とこのAPIの返信が二重に届きます）。「検証」ボタンは、下のGo APIのデプロイが終わるまでは404で失敗するので、まだ押さないでください。

**デプロイ後に必要な作業**

1. **Go APIに、mainを手動でデプロイしてください。** Go APIのVercelプロジェクトは、Gitからの自動デプロイが切れているので（`createDeployments: disabled`）、マージしてもデプロイされません。LINEの機能と、#87のログインの修正は、このデプロイで出ます。Deployments の Redeploy は、古いデプロイを作り直すだけなので使いません。次のどちらかで、mainを明示して出します。
   - Settings → Git で、Gitからのデプロイを入れ直して、mainをデプロイする。
   - プロジェクトをリンクして、mainをチェックアウトした `services/api` から `vercel deploy --prod` を実行する。
2. `curl -i -X POST https://ffpf-zhuelog-api.vercel.app/v1/line/webhook` が `401`（`404` ではない）を返すことを確認してから、LINEの「検証」ボタンを押してください。
3. Webの本番のURLが付いたかを確認してください。WebのVercelプロジェクトの Deployment Checks は、今はないCIのチェック（`verify (24)`・`verify (26)`・`e2e`）を待ち続けるので、本番のURLが付かないことがあります。直すまでは、デプロイを手で Promote します。
4. 本番のGo APIのログに `SQLSTATE 08P01` が出なくなったことを確認してください。
5. 自分のLINEで、連携・添削・翻訳・解除を試してください。

関数の最大実行時間は、`services/api/vercel.json` では指定していません（Goのプリセットでは `functions` のキーが合わず、ビルドが失敗するため）。webhookと拾い直しは最大60秒かかるので、Fluid computeを切るなどして設定を変えるときは、Settings → Functions で60秒以上にしてください。今のプロジェクトは既定が300秒なので足ります。

検証: Goの全テスト（`go test -race`、実際のPostgresを使うテストを含む）、TypeScript単体テスト、ブラウザーE2E（#88で90件）、型チェック、Lint。E2Eでは、ループバックを向いたダミーのLINEの値を使い、実際のLINEとOpenAIには接続していません。PgBouncer越しの名前の衝突そのものは手元で再現できておらず、本番のログで確認します。
