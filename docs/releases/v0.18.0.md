# v0.18.0 — 共通ヘッダーと、アプリ向けのGo APIを追加する

画面上部に全ページ共通のバーを置き、ネイティブアプリ向けのGo API（`services/api`）を追加しました。あわせて、管理者の判定とパスワードログインの制限を見直すセキュリティ修正を入れています。Webのログインとデータの読み書きは、この版ではまだ今までどおりです。

- 全ページ共通のヘッダーバーを追加しました（#73）。アプリ名、ユーザー名とロール（管理者／メンバーのバッジ。ゲストは「ゲスト」）、フォロー、パスワード変更、アカウント管理、ログアウト、テーマ切り替えをまとめています。ログイン画面ではアプリ名とテーマ切り替えだけです。
- 管理者の判定を、GitHubのログイン名から数字のGitHubユーザーIDに変えました（#80）。ユーザー名を変えた管理者の空いた名前を、別の人が取って管理者になれる問題への対応です。
- パスワードログインの制限を、アカウント単位のロックから接続元（IP）単位に変えました（#80）。同じ接続元から同じログインIDへ15分に5回、接続元全体で15分に20回までです（IPv6 は /64 単位）。誰でも他人を締め出せた問題と、IPごとの制限がなかった問題への対応です。`/admin/accounts` の「ロック中」バッジはなくなりました。
- フォローのメンバー一覧に、ログインIDを出さなくしました（表示名だけ）。ログインIDは `/admin/accounts` で確認できます（#80）。
- CSVインポートの上限を 4 MiB に下げました（Vercelの関数が4.5 MBを超える本文を受け取れないため）。アップロードの制限時間も、5分から4分に下げました（#83）。
- Go API（`services/api`）を追加しました（#74・#77・#79・#82）。GitHubログイン（PKCE）とパスワードログイン、短いアクセストークンと使い回しを検知するリフレッシュトークンで認証し、ノートの読み書き、ゴミ箱、共有、フォロー、日付ごとの記録、管理者による会員の閲覧と管理、パスワード変更、CSVインポートを、Webと同じ規則で扱います。Webと同じNeonのDBを使います。
- Go APIをローカルで起動して試す手順（`pnpm run api:db`・`api:dev`・`api:smoke`、`docs/api-local.md`）と、Go APIのドキュメントサイト（VuePress、`pnpm run api-docs:dev`・`api-docs:build`、`docs-site/`）を追加しました（#78・#81）。
- Go APIのデプロイ先は、Cloud Run、AWS ECS Express Modeと検討したあと、最終的にVercelの別プロジェクト（`services/api` をRoot Directoryにする）に決めました（#83）。AWS向けのworkflowは、この版の範囲内で追加してから削除しており、残りません。手順は `docs/api-deployment.md` にあります。
- DBの接続数を、1つのインスタンスあたり5から3に下げました（#83）。

**デプロイ前に必要な作業**

1. Webの Vercel の Production 環境変数に `AUTH_ALLOWED_GITHUB_IDS` を追加してください。値は管理者の数字のGitHubユーザーID（複数はカンマ区切り）で、`https://api.github.com/users/<ログイン名>` の `id` で確認できます。**未設定のままデプロイすると、管理者がログインできなくなります。** 動作を確認したあと、古い `AUTH_ALLOWED_GITHUB_LOGINS` は削除してかまいません。
2. 次の3つのマイグレーションを本番DB（Neon）に適用してください。デプロイより先に行います。いずれもテーブルまたは列の追加だけです。
   - `20261020120000_add_api_refresh_tokens`
   - `20261020130000_add_api_refresh_token_login`
   - `20261021090000_add_sign_in_throttle`

   `20261021090000_add_sign_in_throttle` を適用する前にデプロイすると、ID・パスワードでのログインがエラーになります。

**デプロイ後に必要な作業**

1. 管理者としてGitHubでログインできること、メンバーがID・パスワードでログインできること、`/follow` にログインIDが出ないことを確認してください。
2. Go APIをすぐに使わないなら、この版でVercelのプロジェクトを作る必要はありません（Webはまだ使いません）。作るときの手順は `docs/api-deployment.md` の 2.〜5. です。本番のDBに `ja-x-icu` の照合順序があることも確認してください（`SELECT 1 FROM pg_collation WHERE collname = 'ja-x-icu'`。ないとGo APIの会員一覧が500になります）。

検証: TypeScript単体テスト、Goの全テスト（`go test -race`、実際のPostgresを使うテストを含む）、ブラウザーE2E、型チェック、Lint、ドキュメントのビルド（各PRの確認による）。Vercel上のGo APIは、この版では実際にはデプロイしていません。
