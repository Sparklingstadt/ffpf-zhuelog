# v0.33.0 — 低い画面でも練習の選択肢が隠れないようにし、Lighthouse で測る

**練習の大きさ**

v0.30.0 では、幅 640px 未満のときだけ練習のページを詰めていました。そのため、幅は広いが高さの低い画面では、大きな文字とボタンのままになっていました。たとえば、ブラウザーを最大化していないノートパソコンや、上にデモの帯が出ているときです。その結果、選択肢がタブや画面の下にはみ出し、スクロールが必要でした。

- **大きな表示の条件**：大きな文字とボタンは、幅 640px 以上かつ高さ 896px 以上の画面だけにしました。新しい Tailwind の variant `roomy` と、その逆の `cramped` で切り替えます。それ以外は、スマホと同じ詰めた表示です。
- **詰めた表示**：選択肢の高さを 56px、問題カードの余白を少し小さくしました。
- **自動のスクロール**：開いたときに選択肢が見えていなければ、進捗バーの位置まで自動でスクロールします。これで、問題と 4 つの選択肢が画面に入ります。見出しは、その上にスクロールすれば見えます。
- **単語帳への追加を外す**：練習の正解の画面から、「例文の語句を単語帳に入れる」を外しました。問題と「次へ」を画面に収めるためです。例文の語句は、今日の復習の答えの画面から、これまでどおり単語帳に入れられます。
- **確かめた大きさ**：375×667、375×812、1000×560、1000×650、1024×600、1280×720、1280×1000、1366×640 で、問題と選択肢が最初から見え、正解すると「次へ」も見えることを確かめました。

**Lighthouse**

- Lighthouse 13.6 を開発用の依存に入れ、`pnpm run quality:lighthouse` で本番の 6 ページをスマホと PC で測れるようにしました。ログイン後のページは、デモアカウントで測ります。
- 6 ページとも、性能・ベストプラクティス・SEO が 100 でした。アクセシビリティは学習ノートだけが 96 で、残りは 100 でした（`docs/quality.md`）。

**コントラスト**

学習ノートの「◯箇所を添削」のバッジと、添削の差分（足した文字・消した文字）の文字色を濃くし、4.5:1 を満たすようにしました。ダークの表示では、消した文字を明るい赤にしました。

**デプロイ前に必要な作業**

ありません。Web だけの変更で、マイグレーションも Go API の変更もありません。

**デプロイ後に必要な作業**

1. ブラウザーの窓を低くして（例：高さ 650px）介詞の練習を開き、選択肢がすべて見えることを確かめてください。
