# v0.13.0 — LINEの処理をCloud Runへ移せるようにする

LINEの添削・翻訳をVercelの関数の中で行っていたため、取り残したジョブを拾い直すCronは1日1回で、最大で約24時間待つことがありました。Cronを30分おきにしたうえで、アプリをGoogle Cloud Runでも動かせるようにし、LINEの処理だけをCloud Runへ移す手順を用意しました。Vercelのままでも、これまでどおり動きます。

- LINEの取り残しを拾い直すVercel Cron（`/api/line/drain`）を、1日1回から30分おきにしました。取り残したジョブを待つ時間は、最大で約24時間から約30分になります。30分にしたのは、Cronが動くたびにDB（Neon）が起きるため、無料枠に収めるためです。
- アプリをCloud Runのコンテナとして動かすための `Dockerfile` と、手順書 `docs/cloud-run.md` を追加しました。CIにも `docker build` を加えています。Vercelのビルドとデプロイは変わりません。
- Cloud Shellで実行するスクリプトを追加しました。
  - `scripts/deploy-cloud-run.sh`: Web画面をCloud Runにデプロイします。何度実行しても安全です。
  - `scripts/enable-line-cloud-run.sh`: LINE連携をCloud Runに移します。
- Cloud Runで動かすLINE連携は、webhookが処理待ちを保存したあとCloud Tasksに `/api/line/drain` の呼び出しを頼み、添削・翻訳をそのリクエストの中で行います。これで、Cloud Runをリクエスト課金（`--cpu-throttling`）にできます。タスクの追加に失敗したときは、これまでの `after()` と取り残しの拾い直しに任せます。
- Cloud Runでは、取り残しの拾い直しだけをVercel Cronが行います。LINEを無効にしたVercelの `/api/line/drain` が、同じ `CRON_SECRET` を付けて、`LINE_DRAIN_FORWARD_URL` のCloud Runの `/api/line/drain` に取り次ぎます（`https:` のみ、リダイレクトは拒否、55秒で打ち切り）。LINEが有効なサーバーは、自分で処理します。取り次ぎに失敗したときは、503（`LINE_DRAIN_FORWARD_FAILED`）を返します。
- 権限を失ったセッションのロール名を `user` から `revoked` に変えました。動作は変わりません。
- 依存パッケージを更新しました。`shadcn` と `lefthook` の更新に加えて、`pnpm audit` で見つかった `sharp`・`source-map-js`・`@modelcontextprotocol/sdk` を修正版に上げました。

Vercelだけで動かす場合は、DBのマイグレーションも、新しい環境変数の設定も要りません。

**デプロイ後に必要な作業（LINEをCloud Runで動かす場合のみ）**

1. Cloud Shellで `./scripts/deploy-cloud-run.sh` を実行し、Web画面をCloud Runにデプロイしてください。Cloud Runでは `AUTH_URL`（Cloud RunのURL）が必須です。スクリプトが設定します。
2. 続けて `./scripts/enable-line-cloud-run.sh` を実行してください。Secret Managerへの登録、Cloud Tasksのキューと権限（`LINE_DRAIN_TASKS_QUEUE`）の設定、`/api/line/drain` が200を返す確認までを行います。
3. LINE DevelopersでWebhook URLを `<Cloud RunのURL>/api/line/webhook` に変えて「検証」を押し、自分のLINEから文を送って返信が届くことを確認してください。
4. Vercelの環境変数を `LINE_INTEGRATION_ENABLED=false`・`LINE_DRAIN_FORWARD_URL=<Cloud RunのURL>` にし、`CRON_SECRET` をSecret Managerの `zhuelog-CRON_SECRET` と同じ値にして、再デプロイしてください。値が違うと、Vercelのログに `LINE_DRAIN_FORWARD_FAILED 401` が出ます。
5. Cloud Schedulerのジョブ `zhuelog-line-drain` が残っていれば削除してください（`enable-line-cloud-run.sh` を実行し直すと削除されます）。
6. Vercelの「Cron Jobs」画面から `/api/line/drain` を手動で実行し、Cloud Run側に200の `GET /api/line/drain` があることを確認してください。

この順番なら、切り替えの間に届いたメッセージも取りこぼしません。LINEが無効な側はwebhookに503を返し、LINEが再送します。

検証: TypeScript単体テスト、ブラウザーE2E、型チェック、Lint、`pnpm audit`。Cloud Runの手順は、コンテナのローカル実行（PostgreSQL 17）と、偽の `gcloud` を使ったスクリプトの実行で確認しました。
