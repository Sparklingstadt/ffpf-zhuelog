# 品質の記録

本番の表示速度とアクセシビリティを測った記録です。[就職までのロードマップ](job-hunting-roadmap.md) の J4 です。

## Lighthouse（2026 年 11 月 10 日、v0.32.0）

**測り方**

- `pnpm run quality:lighthouse`（`scripts/lighthouse.mjs`）で、本番を Lighthouse 13.6 で測りました。
- 幅は 2 つです。スマホは Lighthouse の既定のモバイル（回線と CPU を絞った見積もり）、PC はデスクトップの設定です。
- ログインのページはログインせずに測り、そのほかはデモアカウントで入って測りました。
- 毎回、クッキーは残してキャッシュだけを消し、冷えた状態で読み込みます。
- ページごとの HTML の報告は `lighthouse-reports/` に出ます（コミットしません）。

**点数（スマホ / PC）**

| ページ     | 性能      | アクセシビリティ | ベストプラクティス | SEO       | LCP（スマホ） | TBT（スマホ） | CLS |
| ---------- | --------- | ---------------- | ------------------ | --------- | ------------- | ------------- | --- |
| ログイン   | 100 / 100 | 100 / 100        | 100 / 100          | 100 / 100 | 1.1 s         | 20 ms         | 0   |
| 学習ノート | 100 / 100 | 96 / 96          | 100 / 100          | 100 / 100 | 1.1 s         | 10 ms         | 0   |
| 今日の復習 | 100 / 100 | 100 / 100        | 100 / 100          | 100 / 100 | 0.8 s         | 80 ms         | 0   |
| 単語帳     | 100 / 100 | 100 / 100        | 100 / 100          | 100 / 100 | 1.0 s         | 20 ms         | 0   |
| 練習の入口 | 100 / 100 | 100 / 100        | 100 / 100          | 100 / 100 | 1.1 s         | 70 ms         | 0   |
| 介詞の練習 | 100 / 100 | 100 / 100        | 100 / 100          | 100 / 100 | 1.2 s         | 10 ms         | 0   |

**直したこと**：学習ノートのアクセシビリティの 96 は、コントラストの不足が原因でした。v0.33.0 で直しています。

- 「◯箇所を添削」のバッジと、添削で足した文字：明るい緑の地に緑の文字で、4.21〜4.37:1 しかありませんでした。ライトの表示では、文字を濃い緑（`emerald-800`）にしました。
- 添削で消した文字：3.82:1 でした。ライトの表示では濃い赤（`red-700`）、ダークの表示では明るい赤（`red-300`）にしました。

直したあと、手元で axe-core を使い、ライトとダークの両方で学習ノート・日付別・単語帳に WCAG A・AA の指摘がないことを確かめました。

## axe-core と Performance API（2026 年 11 月 10 日、v0.31.0）

**測り方**

- 本番（<https://ffpf-zhuelog.sparklingstadt.com/>）を、Playwright の Chromium で開きました。ゲストでログインできるページだけを測っています。
- 幅はスマホ（390×844）と PC（1280×800）の 2 つです。
- 表示速度は、ブラウザーの Performance API で取りました。TTFB は最初の 1 バイトまで、LCP は最も大きな要素が描かれるまで、CLS はレイアウトのずれです。転送量は、ページとそこから読んだファイルの合計です。
- アクセシビリティは、axe-core 4.13 で WCAG 2.1 A・AA とベストプラクティスを検査しました。
- このときは Lighthouse を入れていませんでした（上の節で測り直しています）。

**表示速度（スマホ / PC）**

| ページ           | TTFB (ms) | LCP (ms)    | CLS   | 転送量 (KB) | うち JS (KB) |
| ---------------- | --------- | ----------- | ----- | ----------- | ------------ |
| ログイン         | 206 / 195 | 2724 / 2096 | 0 / 0 | 359 / 361   | 199 / 199    |
| 練習の入口       | 109 / 26  | 2088 / 732  | 0 / 0 | 22 / 24     | 3 / 3        |
| 介詞の練習       | 120 / 99  | 2464 / 820  | 0 / 0 | 93 / 94     | 70 / 70      |
| 了・过・着の練習 | 28 / 64   | 820 / 1724  | 0 / 0 | 31 / 31     | 10 / 10      |

- **読み方**：ログインのページは、最初の訪問で JS（約 200 KB）をまとめて読みます。そのあとのページは、ほとんどキャッシュから出ます。
- **LCP**：同じページでも 0.7〜2.7 秒とばらつきました。1 回ずつしか測っていないためで、Vercel の関数が起きる時間（コールドスタート）を含む回と含まない回があります。
- **CLS**：どのページも 0 です。テーマの配色を本文より先に当てているので、表示のあとにずれません。

**アクセシビリティ**

| 指摘                                                      | 場所                                        | 対応                                                         |
| --------------------------------------------------------- | ------------------------------------------- | ------------------------------------------------------------ |
| `page-has-heading-one`：h1 がない                         | ログイン                                    | カードの見出し「学习録にログイン」を h1 にした               |
| `color-contrast`（serious）：文字と背景のコントラスト不足 | 練習の HSK の級の、選んでいるボタンの問題数 | 濃い緑の上で `opacity-80` にしていたのをやめ、白のままにした |

どちらも v0.32.0 で直しました。ほかに WCAG A・AA の指摘はありませんでした。

**次に測ること**

- 1 回ずつではなく 5 回ずつ測り、中央値を残します。
